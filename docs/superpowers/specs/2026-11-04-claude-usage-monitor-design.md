# Claude Usage Monitor — дизайн v1

Дата: 2026-11-04
Статус: на согласовании

## 1. Цель и контекст

Собственный продукт: лёгкое кроссплатформенное трей-приложение, показывающее лимиты подписки Claude
(5-часовая сессия, недельный лимит и модельные квоты) в реальном времени.

Вдохновлено проектом [usage-monitor-for-claude](https://github.com/jens-duttke/usage-monitor-for-claude)
(Python + PyInstaller, ~12.5 МБ exe). Код оттуда не копируется — пишем с нуля.

**Ключевые отличия от оригинала:**
- Легче и быстрее: нативный бинарник без Python-рантайма, меньше размер и память, нет ложных
  срабатываний антивирусов, характерных для PyInstaller.
- Полноценная поддержка Windows, macOS и Linux с готовыми установщиками.

**Критерии успеха v1:**
- Установщик/бинарник ≤ 15 МБ на каждой ОС.
- В фоне (попап закрыт) — ≤ 30 МБ RAM на Windows.
- Работает без настройки, если пользователь залогинен в Claude Code.
- Показанные проценты совпадают с тем, что показывает claude.ai → Settings → Usage.

**Не поддерживается:** оплата по API через Anthropic Console (у неё нет таких лимитов).

## 2. Стек

- **Rust + Tauri v2.** Трей — нативный (Tauri tray API), попап — HTML/CSS/vanilla JS в системном WebView
  (WebView2 / WKWebView / WebKitGTK). Без фронтенд-фреймворков и без Node.js в сборке
  (фронтенд — статические файлы, подключаются через `frontendDist`).
- HTTP: `reqwest` (rustls + системные корневые сертификаты через `rustls-platform-verifier`).
- Плагины Tauri: `tauri-plugin-notification`, `tauri-plugin-autostart`, `tauri-plugin-single-instance`,
  `tauri-plugin-positioner`. Локаль: `sys-locale`.
- Сериализация: `serde`, `serde_json`. Время: `time` или `chrono`.
- Иконка трея рисуется в рантайме в RGBA-буфер (крейт `tiny-skia` или вручную).

## 3. Источник данных

### 3.1 Токен

Модуль `credentials` возвращает `Result<String, CredError>`; токен перечитывается **перед каждым
запросом** и нигде не сохраняется и не логируется.

Порядок поиска:
1. Переменная окружения `CLAUDE_CODE_OAUTH_TOKEN` (если задана и не пуста).
2. **macOS:** Связка ключей, generic password с сервисом `Claude Code-credentials` — читается вызовом
   `/usr/bin/security find-generic-password -s "Claude Code-credentials" -w`
   (через системную утилиту, т.к. ACL элемента разрешает её без доп. запроса пароля).
   Если элемента нет — переходим к п. 3.
3. Файл `<config_dir>/.credentials.json`, где `config_dir` = `$CLAUDE_CONFIG_DIR` или `~/.claude`.

Формат (и файла, и значения в Связке ключей): JSON, токен в `claudeAiOauth.accessToken`.
Поле `claudeAiOauth.expiresAt` (мс с эпохи) используется только для диагностики в подсказке
(«токен истёк»), сами мы токен **не обновляем** — это делает Claude Code.

Ошибки: `NotFound` (нет ни одного источника), `Malformed` (JSON/ключи не те), `Io` (в т.ч. чтение
во время записи — повторяем при следующем цикле).

### 3.2 API

Все запросы — `GET` к `https://api.anthropic.com`, таймаут 10 с. Других хостов приложение не трогает.

Заголовки:
- `Authorization: Bearer <token>`
- `anthropic-beta: oauth-2025-04-20`
- `User-Agent: claude-usage-monitor/<version>`

Эндпоинты:
- `/api/oauth/usage` — квоты. Каждое поле верхнего уровня, являющееся объектом с `utilization` (число,
  проценты 0–100) и `resets_at` (ISO-8601 или null), считается квотой. Имя поля — ключ квоты
  (`five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet`, …). Неизвестные ключи показываются
  с «очеловеченным» именем (`seven_day_foo` → «7 дней · Foo»), так что новые типы квот появляются без
  изменения кода. Поля с `utilization: null` пропускаются.
- `/api/oauth/profile` — данные аккаунта (email, тип плана) для шапки попапа. Запрашивается при старте
  и раз в час; ошибки молча игнорируются.

Длительность периода для маркера времени: ключи с префиксом `five_hour` → 5 ч, `seven_day` → 7 дней,
иначе маркер не рисуется.

Маппинг ошибок (`ApiError`):
| Условие | Ошибка | Поведение |
|---|---|---|
| 401 | `AuthExpired` | иконка «!», повтор через 60 с (Claude Code мог обновить токен) |
| 429 | `RateLimited { retry_after }` | ждём `Retry-After`, иначе backoff ×2 (старт 60 с, макс 15 мин) |
| 5xx | `Server` | backoff как у 429 |
| сеть/TLS/таймаут | `Network` | повтор через 60 с, backoff ×2 до 15 мин |
| прочее | `Http(code)` | повтор по обычному расписанию |

## 4. Компоненты (Rust)

Каждый модуль — одна ответственность, логика без UI покрыта юнит-тестами.

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `credentials` | найти и прочитать токен (§3.1) | ОС, fs |
| `api` | HTTP-запросы, разбор ответа в `Vec<Quota>`, маппинг ошибок | `credentials` |
| `model` | типы `Quota { key, utilization, resets_at, period }`, `Snapshot { quotas, fetched_at, profile }`, `AppState` | — |
| `pace` | доля прошедшего периода, флаг «обгоняет темп» | `model` |
| `poller` | расписание запросов (§5), хранит последний `Snapshot` и последнюю ошибку | `api` |
| `alerts` | решает, какие уведомления отправить, по диффу старого/нового снапшота | `model`, `settings` |
| `tray_icon` | рендер RGBA-иконки из `AppState` (2 полосы или «!») | `model`, `pace` |
| `tray` | создание трея, подсказка, меню, клики | `tray_icon`, `i18n` |
| `popup` | создание/уничтожение окна попапа, отправка состояния во фронтенд | `model` |
| `settings` | загрузка необязательного JSON (§6) | fs |
| `i18n` | строки RU/EN, выбор языка | `settings` |

Общее состояние — `Arc<Mutex<AppState>>` в Tauri state; `poller` работает в tokio-задаче и после
каждого обновления вызывает: перерисовку иконки/подсказки, `alerts`, и `emit("state", …)` в попап,
если он открыт.

## 5. Расписание обновлений (`poller`)

- Базовый интервал: **3 мин**, если за последние 15 мин utilization любой квоты менялся; иначе **10 мин**.
- Если ближайший `resets_at` наступает раньше следующего запроса — запрос планируется на `resets_at + 30 с`.
- Пока открыт попап — интервал **1 мин**.
- Ручное обновление (меню / кнопка в попапе) — немедленно, но не чаще раза в 10 с.
- Ошибки — по таблице §3.2 (backoff перекрывает базовый интервал).
- Минимальный интервал между запросами при любых условиях — 30 с.

Расчёт «следующего времени запроса» — чистая функция `next_poll(now, state, settings) -> Instant`,
тестируется без сети.

## 6. Настройки

Необязательный файл `usage-monitor-settings.json`. Порядок поиска: `$CLAUDE_CONFIG_DIR/`, рядом с
исполняемым файлом, `~/.claude/`. Первый найденный используется, остальные игнорируются.
Приложение файл **не создаёт и не изменяет**. Указываются только нужные ключи; ошибка в файле →
используются значения по умолчанию + однократное уведомление «Ошибка в файле настроек: …».

```json
{
  "language": "auto",
  "thresholds": [80, 95],
  "notify_reset": true,
  "pace_alerts": false,
  "poll_active_secs": 180,
  "poll_idle_secs": 600,
  "hidden_quotas": [],
  "tray_bars": ["five_hour", "seven_day"]
}
```

Автозапуск хранится не в этом файле, а средствами ОС через `tauri-plugin-autostart`
(Windows — реестр HKCU Run, macOS — LaunchAgent, Linux — `~/.config/autostart/*.desktop`),
переключается пунктом меню с галочкой.

## 7. Интерфейс

### 7.1 Иконка в трее
- Две горизонтальные полосы (по умолчанию 5 ч сверху, 7 дней снизу), заполнение пропорционально
  utilization. Цвет: обычный — синий; ≥ 80 % — оранжевый; ≥ 95 % или обгоняет темп — красный.
- Фон/контур подстраиваются под светлую/тёмную тему панели (Windows: реестр
  `SystemUsesLightTheme`; macOS: template-иконка не используется, рисуем с контуром; Linux: по
  теме GTK, по умолчанию — светлые полосы на тёмном).
- Состояние ошибки — иконка с «!».
- Рендер в 32×32 (Windows/Linux) и 22×22@2x (macOS).

### 7.2 Подсказка
`5ч: 42% · 7д: 18%`. При ошибке — текст ошибки (`Войдите в Claude Code: claude auth login`).
При устаревших данных — добавка `(обновлено 12 мин назад)`.

### 7.3 Меню (правый клик; на macOS — клик)
Открыть · Обновить · ☑ Запускать при входе · Выход.

### 7.4 Попап
- Открывается левым кликом (Windows/Linux) или пунктом «Открыть»; позиционируется у иконки трея
  (`tauri-plugin-positioner`), без рамки, поверх окон, закрывается по Esc / потере фокуса.
- **Окно уничтожается при закрытии** (не скрывается), чтобы освободить память WebView.
- Содержимое: шапка (email, план), список квот: название, полоса, `42%`, «сброс через 2 ч 14 мин».
  На полосе — тонкая белая вертикальная линия «доля прошедшего периода»; если utilization больше
  неё — полоса красная. Внизу — «Обновлено N мин назад» + кнопка «Обновить».
- Если данные устарели (последний успешный запрос > 2 базовых интервалов назад) — плашка «Данные
  могут быть устаревшими».
- Фронтенд: `index.html`, `popup.css`, `popup.js` — без фреймворков; данные приходят через
  событие `state` и команду `get_state`, тексты — через команду `get_strings`.
- Светлая/тёмная тема по `prefers-color-scheme`.

## 8. Уведомления (`alerts`)

Чистая функция `evaluate(prev: &Snapshot, next: &Snapshot, fired: &mut FiredSet, settings) -> Vec<Alert>`.

- **Порог:** при переходе utilization квоты через порог из `thresholds` — одно уведомление
  («Лимит 5 ч: 80 %, сброс через 1 ч 20 мин»). `FiredSet` хранит `(quota_key, threshold, resets_at)`,
  поэтому в пределах одного периода повторов нет; после сброса — снова можно.
- **Режим темпа** (`pace_alerts: true`): порог срабатывает, только если utilization > доли прошедшего
  периода.
- **Сброс** (`notify_reset: true`): `resets_at` квоты сменился и прежняя utilization была ≥ 80 % →
  «Лимит 5 ч восстановлен».
- Первый снапшот после запуска не порождает уведомлений (нет `prev`).
- `FiredSet` живёт в памяти; после перезапуска пороги, уже превышенные на момент старта, не
  уведомляются (тот же принцип «нет prev»).

## 9. Локализация

Два встроенных файла `locales/ru.json`, `locales/en.json` (`include_str!`). Язык: настройка
`language`, иначе системная локаль (`sys-locale`): `ru*` → ru, всё остальное → en.
Форматирование длительностей («2 ч 14 мин» / «2h 14m») — в Rust, единая функция для трея,
уведомлений и попапа (попап получает готовые строки).

## 10. Обработка прочих ситуаций
- Single instance: второй запуск фокусирует попап первого и завершается.
- Сон/пробуждение: после пробуждения (разрыв между тиками > 2× интервала) — немедленный запрос.
- Linux без поддержки трея (нет AppIndicator) — уведомление и выход с понятным сообщением в stderr.

## 11. Тестирование

Юнит-тесты (`cargo test`), без сети и UI:
- `api`: разбор ответа по JSON-фикстурам (все квоты, null-поля, неизвестные ключи), маппинг HTTP-кодов
  (через абстракцию транспорта / тестовый HTTP-сервер).
- `credentials`: файл есть/нет/битый/без ключа, приоритет env-переменной (macOS-путь — за трейтом,
  подменяемым в тестах).
- `pace`, `poller::next_poll`, `alerts::evaluate`, форматирование длительностей, i18n-выбор языка,
  загрузка настроек (частичный файл, битый файл).

Ручная проверка по чек-листу (`docs/manual-test.md`) на каждой ОС: иконка, тема, подсказка, меню,
попап (открыть/закрыть/Esc/позиция), уведомления (через тестовую команду в debug-сборке),
автозапуск, состояние «нет токена».

## 12. Сборка и выпуск

- Локально: `cargo tauri dev` / `cargo tauri build` (нужен Rust stable + `tauri-cli`).
- CI (GitHub Actions, `tauri-apps/tauri-action`), матрица:
  - Windows x64 → `.msi`, NSIS `.exe`;
  - macOS → `.dmg` (aarch64 + x86_64);
  - Linux x64 → `.deb`, `.AppImage`.
- CI также гоняет `cargo test`, `cargo clippy -D warnings`, `cargo fmt --check`.
- Профиль release: `opt-level = "s"`, `lto = true`, `codegen-units = 1`, `strip = true`, `panic = "abort"`.
